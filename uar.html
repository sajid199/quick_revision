UAR (User Access Review) Cheat Sheet

ECC Security GRC (AC) BRF+ Cheat Sheet MSMP Simulator Fiori Security UAR Review

What is UAR?

A periodic access recertification process built on GRC AC & MSMP — managers or role owners confirm each user's access is still appropriate for their current job/role.

Unwanted or stale access is flagged and removed as part of the review cycle.

Why run it

To check access is appropriate for the current role, and to strip out unwanted access before it becomes a risk.

Audit cadence

Standard audit requirement: run UAR once every 6 months.

Who reviews

Manager or Role Owner — decided via config parameter 2006.

Reviewer Configuration — Manager vs. Role Owner

Param 2006 — Who are the reviewers?

Role Owner
  • No extra system integration required
  • Review task routed to the owner of the role assigned to the user
  • Most common setup when HR/AD data isn't synced to GRC
Selected in this build
Manager
  • Review task routed to the user's line manager
  • Requires LDAP or Active Directory integrated with GRC to resolve manager relationships
  • Without AD/LDAP integration this option cannot resolve reviewers
Needs LDAP/AD
Configured at SPRO > GRC > AC > Maintain Configuration Settings Param 2006 = ROLE OWNER
UAR Implementation Steps
STEP 1

Configure Reviewer Parameters

Set the UAR‑related parameters under Parm Group 07 before touching workflow.

SPRO > GRC > AC > Maintain Configuration Settings
UAR parameters
  • 2004 Request type for UAR
  • 2005 Default priority
  • 2006 Who are the reviewers?
  • 2007 Admin review required before sending tasks to reviewers
  • 2008 Number of line items per UAR request
  • 2062 Send notification to users whose access is removed
STEP 2

Activate UAR Workflow in MSMP

Wire up the MSMP workflow that routes UAR tasks to the chosen reviewer.

SPRO > GRC > AC > Workflow for AC > Maintain MSMP Workflows
  • Select process SAP_GRAC_USER_ACCESS_REVIEW
  • Go to Edit mode, step through to Step 5 — Maintain Paths
  • Only one path: GRAC_DEFAULT_PATH
  • Only one stage: GRAC_DEFAULT_STAGE
  • Set Agent ID = GRAC_UAR_REVIEWER, Approval Type = Any One Approver
  • Step 7: Save & Simulate — validates config, prompts for a Transport Request
  • Activate the workflow — without this, config changes won't take effect
STEP 3

Enable Request Type & Generate UAR Requests

Turn on the UAR request type, then run the two background jobs that create and route the requests.

Enable request type
SPRO > GRC > AC > User Provisioning > Define Request Types
  • Request type 11 — UAR Review must be Active, mapped to MSMP process SAP_GRAC_USER_ACCESS_REVIEW
  • Set parameter 2004 = 011 (UAR Review) at Maintain Configuration Settings
Run the jobs (in order)
NWBC > Access Management > Scheduling > Background Scheduler
  • Job 1 — Activity: "Generates data for access request UAR review" (filter by Business Process, Connector, Critical Level, System Env, Role Name/Sensitivity, User Group/ID/Type, etc.)
  • Job 2 — Activity: "Update Workflow for UAR request" (run once Job 1 completes, non‑recurring)

Check status at NWBC > Access Management > Scheduling > Background Jobs, then open View Results for the event log.

Sample event log
  • Extraction from ERM completed
  • Request to be grouped by role owner
  • Admin review is configured as not required
  • N UAR requests has to be created / Request generation started
  • No co‑ordinator found for user <ID> — role owner/coordinator mapping missing for that user
  • Request generation completed — total requests created: N
STEP 4

Search & Track Requests

Locate generated UAR requests and follow their approval status.

NWBC > Access Management > Access Request Administration > Search Requests
  • Requests are routed per the reviewer configured in param 2006
  • With Role Owner selected, tasks land in the Role Owner's worklist
  • "No co‑ordinator found" warnings mean that user's request needs a manual reviewer fix
