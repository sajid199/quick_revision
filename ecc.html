Security Overview & Importance

SAP Security involves safeguarding SAP systems by managing user access, roles, and authorizations to protect critical business data and maintain compliance with security standards.

Effective SAP Security ensures data integrity, mitigates risks, prevents unauthorized access, and supports regulatory compliance across an organization's integrated SAP landscape.

User Type in SAP

  • Dialog User: individual interactive logins — personal access with standard checks and password expiration
  • System User: background processing, system‑to‑system communication, scheduled tasks — no interactive login
  • Communication User: external RFC connections — secure programmatic access without GUI login
  • Service User: shared user for anonymous/multiple concurrent logins, limited interactive use — often for web services
  • Reference User: assigned to other users to grant additional roles/authorizations without direct logon capability (used when a user's profile assignment would exceed 312 profiles)

Role Type in SAP

  • Single Role: a set of specific authorizations assigned to users, providing access to perform designated tasks
  • Composite Role: groups multiple single roles together, simplifying user role assignment by bundling related authorizations
  • Derived Role: inherits authorizations from a master role, allowing organizational‑level customization while keeping a consistent structure
  • Master Role: a template role that acts as the source for derived roles — contains all authorizations without organizational values filled in

Access Issue

  • SU53 — displays the last authorization check that failed
  • ST01 / STAUTHTRACE — set trace on a user ID to check missing authorization
Return codes for trace
RC = 0

Authorization check successful.

RC = 4

Check unsuccessful — user has the authorization object in their buffer, but with different values than checked.

RC = 12

Check unsuccessful — user does not have the authorization object in their buffer at all.

PFCG Traffic Indicator

Red — some organizational value has not been maintained in the org field in Profile Generator.

Yellow — some or all fields in certain authorization instances are blank (not maintained).

Green — all authorization fields are maintained (values are assigned).

USOBX_C & USOBT_C

Both tables are used by SU24.

  • USOBX_C: defines the status of authorization checks for authorization objects (check indicator = Yes/No), and whether check values are maintained in SU24.
  • USOBT_C: defines the actual "values" maintained for check‑maintained authorization objects.

SU24

Check / No

Authorization object is checked at t‑code execution, but no field value is proposed when the t‑code is added to the role menu.

Check / Yes

Object is checked at execution and automatically pulled into the role when the t‑code is added to the menu — may or may not carry field values, depending on what's maintained in SU24.

Do Not Check

Object is not checked at all, even though it may still exist in the ABAP code.

SU25 Steps

  1. Step 1 — Initial Fill: used the first time Profile Generator is set up (or to reload every SAP default) — copies SAP's default check indicators & field values into the customer tables (USOBT_C/USOBX_C).
  2. Step 2a — Prepare Comparison: run first, after an upgrade, to prepare the comparison between your existing SU24 data and the new SAP defaults.
  3. Step 2b — Compare & Adjust: shows SAP's new default values next to your existing ones so you can adjust check indicators/field values — same maintenance screen as SU24.
  4. Step 2c — Roles to Be Updated: flags which roles are affected by the changes with status "profile comparison required," so their profiles can be regenerated (or SAP_NEW can be assigned as a temporary stopgap).
  5. Step 2d — Transaction Replacements: lists roles containing transaction codes SAP has replaced with new ones, so they can be swapped.
  6. Step 3 — Transport: transports the changes made in Steps 1, 2a and 2b to other systems.
  7. Step 4 — Tailor Authorization Checks: same maintenance as calling SU24 directly — edit check indicators per transaction (Check/Maintain adds the object to Profile Generator; Do Not Check skips it).

Profile Generation — Expert Mode (PFCG)

When you regenerate a profile in PFCG (Authorizations tab → Change Authorization Data → Utilities → Expert Mode), Expert Mode gives you exactly three options for how existing authorization data is treated against the current menu / SU24 defaults. The option you pick determines what survives the regeneration.

Destructive

Delete and Recreate Profile and Authorizations

Wipes out all existing authorization data and rebuilds the profile completely fresh from current SU24 defaults.

  • All custom / manually changed field values are lost
  • Use only when you deliberately want a clean rebuild
  • Avoid on roles with hand‑maintained field values
No comparison

Edit Old Status

Loads the last‑saved authorization data as‑is — no comparison is run against the role menu or SU24 updates.

  • Ignores any t‑codes added or changed in the role menu
  • Open fields already present will not be flagged for update
  • Useful only for touching up existing values, not for menu changes
Recommended

Read Old Status and Merge with New Data

Compares the current role menu / SU24 data against existing authorizations, pulls in new objects, and retains old customized values.

  • Standard option for day‑to‑day role maintenance
  • Always the correct choice when generating derived roles
  • Never use "Delete and recreate" on a derived role

Rule of thumb: use Read old status and merge with new data for routine maintenance and derived‑role generation; reserve Delete and recreate for a genuine clean‑slate rebuild, since it discards every manually maintained field value.

Interview Quick Notes — SU24 vs SU25

When to Use SU24

In simple terms: SU24 is where you tell the Profile Generator what to propose for a transaction before anyone builds a role with it. Use it when:

Wrong link

An authorization object is not linked correctly to a transaction code — fix the transaction → object relationship in SU24.

Bad default value

An authorization object has an unacceptable default value proposed — correct the value SU24 proposes when the t‑code is added to a role.

Reusable across roles

You want a default that works for every role that will ever use the transaction — usually means leaving the field blank in SU24, so each role can maintain its own value instead of inheriting a fixed one.

One-liner for the interview: "SU24 controls what the Profile Generator proposes for a t‑code — I use it to fix incorrect object/t‑code links and bad default values, and to keep fields blank when different roles legitimately need different values."

SU25 in Simple Terms

SU25 is the one‑time / post‑upgrade tool that loads SAP's SU24 defaults into your customer tables and lets you compare them after an upgrade — SU24 is for ongoing, transaction‑by‑transaction maintenance.

Why use it

After an SAP upgrade, new/changed authorization checks ship with new SU24 defaults. SU25 walks you through adopting them without losing what you already customized.

First time vs. after upgrade

First time using Profile Generator → run Step 1 (initial fill). Already using it, now upgrading → run Steps 2a → 2b → 2c → 2d in that order.

SU24 vs SU25

SU24 = maintain proposals for one transaction at a time, anytime. SU25 = bulk‑load/compare SAP's defaults, mainly right after an upgrade; Step 4 of SU25 drops you into the same screen as SU24.

One-liner for the interview: "SU25 is the upgrade tool that syncs the customer authorization tables with SAP's new SU24 defaults and tells me which roles need regeneration; SU24 is what I use day‑to‑day to fine‑tune one transaction's proposal."
