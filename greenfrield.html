Implementation lifecycle

Security built in from day one

Greenfield means a brand new S/4HANA system built from scratch, so business processes, data and security are all designed fresh. SAP Activate runs the project in five phases (Prepare, Explore, Realize, Deploy, Run), and each phase ends with a Quality Gate. Security designs and builds the access: roles, users, Fiori apps and Segregation of Duties (SoD) controls.

01
SAP Activate · Prepare

Project setup & strategy

Define the security roadmap, governance framework and initial landscape access.

Key activities

  • Appoint security workstream owners; agree RACI, decision forums and escalation paths.
  • Confirm system landscape, clients, identity source, authentication approach and access provisioning model.
  • Set security principles: least privilege, role ownership, naming standards, emergency access and SoD controls.
  • Plan environments, transport routes, privileged access and time-bound project access.
  • Identify regulatory, audit, data-protection and security requirements.

Exit with

Approved security strategy and RACI, landscape/access matrix, role-design standards, control requirements, delivery plan and initial risk register.

Say it simply: In Prepare I build nothing. I learn the scope, the business owners and the BPML, and agree the security approach, so there is no rework later.
02
SAP Activate · Explore

Fit-to-standard & blueprinting

Gather business requirements, identify standard roles and map Fiori access.

Key activities

  • Run fit-to-standard workshops by business process; record job roles, tasks and approval responsibilities.
  • Map SAP-delivered business roles, catalogs, spaces and pages to the agreed personas.
  • Identify gaps, custom apps, sensitive transactions, interfaces, batch users and technical accounts.
  • Perform initial SoD and critical-access analysis; agree mitigation or process changes.
  • Define role boundaries, derived-role strategy, organizational values, naming and ownership.

Exit with

Approved role-to-persona matrix, Fiori app/catalog mapping, authorization design, SoD rules and mitigations, gap backlog and security requirements traceability.

Say it simply: Explore is the most important phase for security. I turn business processes into job roles and an authorization matrix, agree SoD rules with audit, and get a sign-off before anything is built.

03
SAP Activate · Realize

Role building & system hardening

Build, configure and mass-generate security roles in the Development environment.

Key activities

  • Configure security baselines and review relevant system, client, password, audit-log and trusted-connection settings.
  • Build and document single, composite and derived roles in PFCG; add Fiori catalogs and spaces/pages as designed.
  • Maintain authorization values and organizational levels; generate profiles and run user comparison.
  • Implement technical-user controls, firefighter/emergency access and required GRC risk rules or mitigations.
  • Unit-test roles and services; resolve SU53/STAUTHTRACE findings and move changes through controlled transports.

Exit with

Generated and documented DEV roles, reviewed configuration baseline, tested Fiori content, technical-user inventory, transport evidence and an updated risk/control register.

Say it simply: In Realize I build roles in PFCG from the matrix, set up Fiori catalogs, test with SU53 and STAUTHTRACE, run the SoD analysis, and transport roles to QAS before testing starts.

04
SAP Activate · Deploy

Testing & migration to production

Validate roles through rigorous testing, execute cutover and go live.

Key activities

  • Transport roles and configuration through QAS using approved change and release controls.
  • Execute role-based functional, negative authorization, Fiori launchpad, integration and regression tests.
  • Complete business-user UAT, SoD/risk analysis, privileged-access checks and remediation sign-off.
  • Reconcile approved user-to-role assignments; prepare provisioning, firefighter and break-glass procedures.
  • Rehearse cutover, validate production role generation and user comparison, and confirm go/no-go evidence.

Exit with

Signed test evidence and risk acceptance, approved production transports and access list, cutover checklist, rollback/escalation plan and production readiness approval.

Cutover control: Grant only approved, reconciled access. Track emergency access with an owner, expiry and post-use review.
Say it simply: In Deploy I run the security part of cutover in order: roles first, then users, then assignments, then emergency access. I rehearse it in the mock cutover so go-live has no surprises.
05
SAP Activate · Run

Hypercare & operations

Stabilize the system, manage access requests and maintain continuous compliance.

Key activities

  • Operate a hypercare queue for access issues; triage, trace, resolve and document recurring defects.
  • Process joiner/mover/leaver and role-change requests through approved workflows and owner approvals.
  • Review SoD conflicts, emergency access logs, privileged and technical accounts, and role changes.
  • Run periodic user access reviews; remove stale access and track remediation to closure.
  • Manage releases, role redesign and transports with regression tests, evidence retention and control monitoring.

Operate with

Service-level targets and ownership, access-request procedures, recurring risk and UAR schedule, audit-ready evidence, metrics dashboard and continuous-improvement backlog.

Say it simply: In Run I keep access correct through tickets, periodic reviews and SoD monitoring, and hand over full documentation so support can continue without the project team.

Interview ready

60-second answer

The answerIn a greenfield S/4HANA project I follow SAP Activate. In Prepare I understand the scope. In Explore I create the authorization matrix and SoD rules with business owners. In Realize I build and test roles, set up Fiori catalogs, run SoD analysis and transport roles to QAS. In Deploy I move roles to production, create users and set up firefighter access. In Run I handle tickets and access reviews.

One-line versionUnderstand scope, design the matrix, build and test roles, deploy users and access, then support and audit.

Common questions

Short answers to practise

What is your daily routine?Use your real work: role changes, user administration, authorization issues with SU53 and ST01, GRC workflow requests, SoD mitigation and audit requests. Give one real example.

A tester reports a missing authorization. What do you do?Check SU53 or STAUTHTRACE, find the missing object and values, fix the role in DEV, transport it, then retest.

How do you avoid SoD conflicts in role design?Keep risky functions in separate roles, run ARA simulation before assigning, and use mitigating controls only when a conflict cannot be avoided.

Why do roles go before users in cutover?Users without roles cannot work, and creating users first causes access errors and rework.

ASAP or Activate?ASAP was used for ECC projects. Activate is used for S/4HANA and has the Prepare, Explore, Realize, Deploy and Run phases.

What is Fiori security in two parts?The front end decides which tile the user sees (catalogs, groups, spaces and pages). The back end decides what the user can do (PFCG authorizations and OData service authorization).

Across every phase

Security delivery guardrails

Least privilegeDesign access around job tasks, not convenience or copied legacy roles.

TraceabilityLink requirements, role decisions, approvals, tests and transports.

Segregation of dutiesIdentify conflicts early; remediate or document approved mitigations.

Controlled changeSeparate development, approval and production access wherever practical.
