What is BRF+

Business Rule Framework Plus is an ABAP‑based rules engine, part of the NetWeaver stack, used to define and execute business rules without hard‑coding logic into ABAP.

A Function receives Context (input) and returns a Result, evaluated through rule sets and expressions such as decision tables, formulas, and rules.

Transaction: BRF+ / BRFPLUS

What is MSMP

Multi‑Stage Multi‑Path is GRC's workflow engine — it lets you build flexible, condition‑based approval workflows for ARM, EAM (FF log review), and BRM.

Every workflow is built from a Process ID, an Initiator Rule, one or more Paths, and Stages with assigned Agents.

BC Set: GRC_MSMP_CONFIGURATION

How they work together

MSMP is the workflow shell — it decides which path and stage a request goes through. BRF+ is the decision engine behind it — it decides who approves and which path is triggered.

MSMP calls BRF+ for two things: Initiator Rules (which path to route to) and Agent Rules (who the approver is at a stage).

Rule shells are generated from MSMP via GRFNMW_DEV_RULES, then built out inside BRF+.

Core Components
BRF+

Application & Function

The container and the interface: every rule lives inside an application, and every application exposes one or more functions.

Building blocks
  • Application: top‑level container — holds functions, data objects, rule sets
  • Function: the interface between the calling program and the rules — defined by Context (input) + Result (output)
  • Data Object: element, structure, or table used inside expressions
  • Ruleset: a group of rules assigned to exactly one function; priority (0–99) sets execution order
  • Event mode: function runs its rule sets in priority order at runtime
  • Changing to Event mode resets the result data object — must be reconfigured manually
Key transaction
BRF+ / BRFPLUSGRFNMW_DEV_RULES
BRF+

Expression Types

Expressions hold the actual logic inside a rule set — the decision table is the most commonly used in GRC agent/initiator rules.

  • Decision Table: maps input column combinations to a result row — easiest to read and maintain
  • Decision Tree: branches sequentially on conditions
  • Formula: performs calculations on data objects
  • Rule / Boolean: combines conditions with AND / OR / NOT
  • Procedure Call: calls a function module or class method
  • Database Lookup: reads values from a custom or standard table
Common GRC use in AC
  • Agent rule via DB Lookup on a custom table
  • Agent rule via role membership (users assigned to a PFCG role)
  • Initiator rule to route requests to different paths
MSMP

Process, Path & Stage

The structural hierarchy of a workflow — every request follows exactly one path made of ordered stages.

  • Process ID: the workflow scenario, e.g. SAP_GRAC_ACCESS_REQUEST
  • Initiator Rule: one active rule per Process ID — decides which path (Rule Result) a request takes
  • Path: a defined sequence of approval stages (e.g. Manager → Security → Role Owner)
  • Stage: a single approval step within a path, with its own agent(s)
  • Route Mapping: links a request's attributes to the correct path/stage combination
Notifications
  • Configured per Agent + Event + Template
  • Sent on REQUEST_SUBMISSION or END_OF_REQUEST
  • Templates reference an SE61 document; variables personalize the message
MSMP

Agents & Rule Types

An Agent ID tells MSMP who should act at a stage. GRC supports four ways to determine that agent.

  • Directly mapped users: a fixed user or small team handles the stage
  • PFCG role‑based: whoever holds a given role in the GRC system becomes approver
  • User group‑based: all members of a defined user group are notified
  • GRC API rules (BRF+): dynamically determines the owner from conditions (e.g. module‑based routing to FI vs SD security teams)
Rule categories in Maintain Rules
Function Module ruleABAP Class ruleBRF+ rule

All three appear as GRC API Rules when assigning an Agent Type in MSMP.

Configuration Flow & Reference

Build an ARM Workflow — Step by Step

  1. Activate BC Set — SPRO → GRC → Access Control → Workflow for Access Control → Activate MSMP BC Set (GRC_MSMP_CONFIGURATION)
  2. Define initiator & agent rules in BRF+ (generate rule shell via GRFNMW_DEV_RULES, build logic in BRF+)
  3. Maintain Rules in MSMP — register the new rule so it's available for selection
  4. Add Agent Rule — MSMP Workflow Configuration → Maintain Agent Rule → add rule details & rule result
  5. Maintain Agents — add new Agent ID as a GRC API Rule under MSMP → Maintain Agents
  6. Create path & stages — add stages and assign approvers/agents to each stage
  7. Set Global Initiator — MSMP → Global Rules → assign the new Initiator Rule
  8. Generate, Simulate & Activate — MSMP → Generate Versions → Save → Simulate → Activate

Glossary

Context
The importing parameters passed into a BRF+ function — the "input" of the rule.
Result
The output parameter returned by a BRF+ function after rule evaluation.
Rule Result
The value an Initiator Rule returns, used by MSMP to pick which path a request follows.
Agent ID
A named reference in MSMP that resolves to one or more approvers at a stage.
Priority (0–99)
Execution order of rule sets within a BRF+ function — 0 runs first.
Simulate
MSMP's built‑in test step to validate path/stage/agent logic before activating a workflow.
